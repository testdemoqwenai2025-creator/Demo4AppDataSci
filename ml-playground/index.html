  • Lakehouse5The lake→lakehouse evolution: Hadoop → S3+Hive → Iceberg/Delta/Hudi. Vendor-neutral open table formats giving ACID + SQL to cheap object storage. Anchor page for the Data Lakehouse group.

Mathematics of BDT — what the sliders actually control
LaTeX
Gradient Boosting builds an additive model F_M(x) = Σ ν · h_m(x) by sequentially fitting each tree h_m to the negative gradient of the loss. Every slider here maps to a term in these equations.

1. Additive model (the boosting update rule)

Fm(x)=Fm−1(x)+ν⋅hm(x)F_m(x) = F_{m-1}(x) + \nu \cdot h_m(x)Fm​(x)=Fm−1​(x)+ν⋅hm​(x)

ν = learning_rate slider (0.01–1.0). h_m = the m-th decision tree. Each tree corrects the residual error of the ensemble so far. Smaller ν → need more trees (m_max = n_estimators slider).

2. Binomial deviance loss (what we minimise)

L(y,F)=log⁡ ⁣(1+e−2yF),y∈{−1,+1}L(y, F) = \log\!\bigl(1 + e^{-2yF}\bigr), \quad y \in \{-1, +1\}L(y,F)=log(1+e−2yF),y∈{−1,+1}

Equivalent to logistic-regression log-loss. The negative gradient (pseudo-residual) is r_m = 2y / (1 + e^(2yF)) — each tree fits this residual.

3. Tree depth = interaction order

hm(x)=CART(x; depth=d)h_m(x) = \text{CART}(x;\, \text{depth} = d)hm​(x)=CART(x;depth=d)

max_depth = d slider. A depth-3 tree can express 3-way feature interactions (e.g. “high pT AND low τ21 AND high b-tag”). Depth 1 = pure additive model (like logistic regression). Depth 10 = can memorise training noise.

4. ROC curve & AUC

AUC=∫01TPR(FPR−1(t)) dt\text{AUC} = \int_0^1 \text{TPR}(\text{FPR}^{-1}(t))\, dtAUC=∫01​TPR(FPR−1(t))dt

TPR = TP / (TP + FN); FPR = FP / (FP + TN). AUC = probability that the model ranks a random signal higher than a random background. AUC = 0.5 = random; AUC = 1.0 = perfect.

5. Confusion matrix → precision / recall / F1

Precision=TPTP+FP,Recall=TPTP+FN\text{Precision} = \frac{TP}{TP + FP}, \quad \text{Recall} = \frac{TP}{TP + FN}Precision=TP+FPTP​,Recall=TP+FNTP​
F1=2⋅Precision⋅RecallPrecision+RecallF_1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}F1​=2⋅Precision+RecallPrecision⋅Recall​

Threshold = 0.5 by default. For LHC you tune for HIGH recall (don't miss Higgs). For fraud detection you tune for HIGH precision (don't freeze customer cards).

Slider → math mapping (cheat sheet)

  • n_estimators → m (number of boosting rounds)
  • max_depth → d (interaction order in each tree)
  • learning_rate → ν (shrinkage on each tree)
  • feature selection → which x_i are visible to the CART splits

Why this matters — training vs inference
Every other card on the platform runs pre-written code (inference). This page lets you TRAIN the model — and feel the tradeoffs.

A reader who sees a pre-trained BDT ROC curve (AUC=0.82) learns a fact. A reader who TRAINS that BDT themselves — adjusting tree depth from 3 to 5, watching AUC go from 0.78 to 0.85 but training time from 2s to 8s — learns a tradeoff. The tradeoff IS the data science. The playground makes tradeoffs visceral.

Every slider reveals a tradeoff:

  • n_estimators: more trees → better AUC but slower training + overfitting plateau
  • max_depth: deeper trees → more capacity but overfitting (train AUC > test AUC)
  • learning_rate: higher → faster convergence but noisier (less stable)
  • feature selection: fewer features → simpler model, lower AUC, but more interpretable

The BDT → CNN → GNN evolution: The BDT here (engineered features, AUC~0.82) is the baseline. On the LHC page, the CNN (jet images, AUC~0.89) and GNN (particle graphs, AUC~0.93) improve by capturing spatial structure. But the BDT is always the starting point — fast, interpretable, and good enough for a first analysis. The practicing DS knows: try the simple model first.

My deeper thoughts — ML Playground

These are not summaries. They are arguments — the kind of connections a reader with serious grey matter would make after living with the material for years. Each thought connects to the platform's research section (ADRs, papers, decision records) so it's traceable, not just opinionated.

The bias-variance tradeoff IS the slider you can feel

Connected to: Phase 8: living-equations cards →

In a textbook, “bias-variance tradeoff” is a U-curve drawn once and forgotten. Here it's the depth slider. Depth=1 = high bias (underfits), depth=10 = high variance (overfits). The minimum on the U-curve is dataset-dependent — that's why no textbook can tell you “use depth 3” with a straight face. You tune it. The playground makes the U-curve something you can FEEL by watching the train-test AUC gap open and close as you drag the slider.

Loss curves lie — until you draw the test one too

Connected to: Phase 1: architecture →

Every ML tutorial shows a training loss curve going down. That curve ALWAYS goes down — boosting fits residuals, residuals shrink, loss decreases. The curve carries no information by itself. The INFORMATIVE curve is the test loss, plotted alongside. It goes down, then flatlines, then rises. The inflection point is the optimal number of trees — past it, you're memorising noise. Without the test curve, you cannot see overfitting. This is why we plot both — and why scikit-learn's staged_predict_proba is the most underused method in the library.

Feature importance is the Pareto principle made visible

Connected to: Elegant Code: SVD, attention →

The feature-importance chart almost always shows the top 3 features carrying 70–80% of the total importance. This is the Pareto principle (80/20 rule) appearing in ML — and it's the reason feature selection works at all. The corollary: the bottom 30% of features contribute almost nothing. In production you'd drop them and retrain: simpler model, ~same AUC, faster inference, lower memory. The BDT's feature_importances_ attribute is the cheapest feature-engineering signal you'll ever get — and it's free after every training run.

Precision vs recall is the ethics of thresholding

Connected to: LHC + finance + insurance pages →

The default threshold of 0.5 is a convention, not a law. For LHC (signal = Higgs), recall matters more than precision — you don't want to lose a Nobel prize because the threshold was too high. For fraud detection, precision matters more — false positives freeze customer cards and erode trust. For insurance claims, the right threshold depends on the cost of investigation vs the cost of payout. The AUC is threshold-independent (that's its strength); the confusion matrix IS threshold-dependent (that's its strength). You need both. Thresholding is where ML meets business logic — and where data scientists earn their salary.

BDT → CNN → GNN is the universal ML evolution

Connected to: LHC data analysis page + molecular modelling →

On the LHC page, the BDT (engineered features, AUC~0.82) is the baseline. The CNN (jet images, AUC~0.89) captures 2D spatial structure. The GNN (particle graphs, AUC~0.93) captures the irregular topology of particle decay. The same progression appears in protein folding (sequence → contact map → graph), in fraud (transaction features → user session graph → bipartite user-merchant graph). The pattern: engineer features → let the model learn spatial features → let the model learn graph structure. Each step adds ~5–10 AUC points. Each step also adds 10–100× compute. The playground is step 1 of that ladder — and the ladder never ends.

Every hyperparameter is a bet on the data

Connected to: Causal inference page →

n_estimators=100 says “I believe 100 rounds of boosting will saturate the signal”. max_depth=3 says “I believe 3-way interactions are the ceiling of useful structure”. learning_rate=0.1 says “I believe the signal is strong enough that 10% of each tree's correction is safe to add”. None of these are right a priori — they're educated bets. The practicing data scientist tunes not because the defaults are wrong, but because every dataset has its own structure. The playground is the place where these bets become evidence in seconds, not hours.

Why this matters — training vs inference
Every other card on the platform runs pre-written code (inference). This page lets you TRAIN the model — and feel the tradeoffs.

A reader who sees a pre-trained BDT ROC curve (AUC=0.82) learns a fact. A reader who TRAINS that BDT themselves — adjusting tree depth from 3 to 5, watching AUC go from 0.78 to 0.85 but training time from 2s to 8s — learns a tradeoff. The tradeoff IS the data science. The playground makes tradeoffs visceral.

Every slider reveals a tradeoff:

  • n_estimators: more trees → better AUC but slower training + overfitting plateau
  • max_depth: deeper trees → more capacity but overfitting (train AUC > test AUC)
  • learning_rate: higher → faster convergence but noisier (less stable)
  • feature selection: fewer features → simpler model, lower AUC, but more interpretable

The BDT → CNN → GNN evolution: The BDT here (engineered features, AUC~0.82) is the baseline. On the LHC page, the CNN (jet images, AUC~0.89) and GNN (particle graphs, AUC~0.93) improve by capturing spatial structure. But the BDT is always the starting point — fast, interpretable, and good enough for a first analysis. The practicing DS knows: try the simple model first.

My deeper thoughts — ML Playground

The bias-variance tradeoff IS the slider you can feel

Connected to: Phase 8: living-equations cards →

In a textbook, “bias-variance tradeoff” is a U-curve drawn once and forgotten. Here it's the depth slider. Depth=1 = high bias (underfits), depth=10 = high variance (overfits). The minimum on the U-curve is dataset-dependent — that's why no textbook can tell you “use depth 3” with a straight face. You tune it. The playground makes the U-curve something you can FEEL by watching the train-test AUC gap open and close as you drag the slider.

Loss curves lie — until you draw the test one too

Connected to: Phase 1: architecture →

Every ML tutorial shows a training loss curve going down. That curve ALWAYS goes down — boosting fits residuals, residuals shrink, loss decreases. The curve carries no information by itself. The INFORMATIVE curve is the test loss, plotted alongside. It goes down, then flatlines, then rises. The inflection point is the optimal number of trees — past it, you're memorising noise. Without the test curve, you cannot see overfitting. This is why we plot both — and why scikit-learn's staged_predict_proba is the most underused method in the library.

Feature importance is the Pareto principle made visible

Connected to: Elegant Code: SVD, attention →

The feature-importance chart almost always shows the top 3 features carrying 70–80% of the total importance. This is the Pareto principle (80/20 rule) appearing in ML — and it's the reason feature selection works at all. The corollary: the bottom 30% of features contribute almost nothing. In production you'd drop them and retrain: simpler model, ~same AUC, faster inference, lower memory. The BDT's feature_importances_ attribute is the cheapest feature-engineering signal you'll ever get — and it's free after every training run.

Precision vs recall is the ethics of thresholding

Connected to: LHC + finance + insurance pages →

The default threshold of 0.5 is a convention, not a law. For LHC (signal = Higgs), recall matters more than precision — you don't want to lose a Nobel prize because the threshold was too high. For fraud detection, precision matters more — false positives freeze customer cards and erode trust. For insurance claims, the right threshold depends on the cost of investigation vs the cost of payout. The AUC is threshold-independent (that's its strength); the confusion matrix IS threshold-dependent (that's its strength). You need both. Thresholding is where ML meets business logic — and where data scientists earn their salary.

BDT → CNN → GNN is the universal ML evolution

Connected to: LHC data analysis page + molecular modelling →

On the LHC page, the BDT (engineered features, AUC~0.82) is the baseline. The CNN (jet images, AUC~0.89) captures 2D spatial structure. The GNN (particle graphs, AUC~0.93) captures the irregular topology of particle decay. The same progression appears in protein folding (sequence → contact map → graph), in fraud (transaction features → user session graph → bipartite user-merchant graph). The pattern: engineer features → let the model learn spatial features → let the model learn graph structure. Each step adds ~5–10 AUC points. Each step also adds 10–100× compute. The playground is step 1 of that ladder — and the ladder never ends.

Every hyperparameter is a bet on the data

Connected to: Causal inference page →

n_estimators=100 says “I believe 100 rounds of boosting will saturate the signal”. max_depth=3 says “I believe 3-way interactions are the ceiling of useful structure”. learning_rate=0.1 says “I believe the signal is strong enough that 10% of each tree's correction is safe to add”. None of these are right a priori — they're educated bets. The practicing data scientist tunes not because the defaults are wrong, but because every dataset has its own structure. The playground is the place where these bets become evidence in seconds, not hours.
